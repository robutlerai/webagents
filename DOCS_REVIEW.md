# WebAgents public documentation: final review

## Verdict

These docs are broad, well sectioned and in places genuinely good, and they are not yet something a developer can trust. The structure is right: a landing page, a quickstart with test-executed examples, a protocol specification, guides, a skill reference, an API reference. Several pages already meet the bar on their own: `guides/self-registration.md`, `protocols/aoauth.md`, `skills/local/secrets.md`, and the credential-floor table in `agent/transports.md`. The problem is accuracy and reachability, not ambition. The first Python line on the landing page raises ImportError. Every TypeScript agent example in the tree answers "No LLM skill available to process request". The whole `docs/server/` section imports from a subpath the package does not export. Twenty-six pages link a parity matrix that is not published. Three sidebar allowlists hide a six-page section, four of seven guides, and the one page that explains how to pay for a service. All eight Platform API reference pages fail to render. A newcomer who reads top to bottom, copies and runs, fails on both language tabs inside ten minutes, and the developer with no SDK is never told where to start. The good news is that most fixes are line edits against code that already works: the SDK is ahead of its documentation, not behind it.

## The two audiences

**SDK developer, Python.** Best served, and still hits walls. The quickstart's generated examples run. Beyond it: wrong import paths (`pricing` from the package root, `ShortTermMemorySkill`, the hooks decorator, `tool` from `webagents.agents.skills`), hook context fields that do not exist on `Context`, a `Context` described as dict-like when it is not subscriptable, skill-lookup patterns that read `self.agent` before it is set, `PricingInfo` returned bare so the tool bills nothing, and a CLI section that documents commands the binary does not register. The Python x402 (HTTP 402 payment flow) quick start fails at settlement because the skill calls a client attribute the installed client does not have.

**SDK developer, TypeScript.** Badly served. Not one TypeScript agent example in 101 pages can answer a request, because the docs assume `model:` provisions a provider skill and it does not. The class name of every LLM skill is invented (`OpenAILLMSkill` and family). No page says the SDK needs `experimentalDecorators`, ships as ESM (ECMAScript modules) only, or how to run a `.ts` file. `@tool` without `parameters` is advertised to the model as taking no arguments, and nothing says so. `docs/server/` is written against an API that does not exist (`createAgentApp({ agents })`, `serve(app)`, `host:`, `webagents/server/node`). `ctx.auth?.userId`, `getContext`, `context.payments` are all wrong. A TypeScript reader cannot find one correct LLM skill construction anywhere on the site, so search cannot rescue them.

**External agent developer (HTTP, RFC 9421 request signing, reads a 402).** The three pages they need exist and are largely accurate: `protocols/aoauth.md`, `guides/self-registration.md`, `skills/robutler/payments-x402.md`. They are never presented as a sequence, the third is not in the sidebar, and its payments HTTP examples are wrong for all three endpoints. Nothing states that an ownerless account has no payer, so a successful registration is followed by a 402 the developer cannot satisfy or explain. No page shows the registration request and its response, no page gives a signature vector to check a signer against, and the "Platform API" reference that would be their entire interface returns HTTP 500 on all eight pages. Plainly: this audience has the material and no path through it.
